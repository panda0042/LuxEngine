# 에디터 작업 공간

에디터의 기본 틀을 문서 중심으로 정리했다. 상단에는 레벨·애니메이션·스크립트 전환, 공통 재생 제어, 프로젝트 이름, 명령 검색을 둔다. 레벨 도구와 각 문서의 도구는 해당 작업 공간에만 표시한다.

## 배치와 작업 흐름

- 레벨: 왼쪽 Hierarchy와 배치 도구, 중앙 Scene/Game, 오른쪽 Inspector, 아래 콘텐츠·콘솔·문제·디버거 도크다. 콘텐츠는 `Ctrl+Space`로 열고 닫는다.
- 애니메이션: 독립 에셋 편집기와 격리 프리뷰·타임라인·상태 그래프다.
- 스크립트: 왼쪽 프로젝트 C# 파일, 중앙 파일 탭과 코드, 오른쪽 클래스·함수 목록, 아래 문제·빌드 출력이다.
- 레벨에서 다른 작업 공간으로 갔다가 돌아오면 레벨의 도크 배치를 복원한다. 애니메이션에서 스크립트로 바로 전환해도 레벨 배치를 덮어쓰지 않는다.
- 재생 제어는 작업 공간을 바꿔도 상단에 남는다. Scene/Game 선택과 현재 씬은 문서 전환 중 유지한다.

배치 형식 버전을 6으로 올렸다. 이전 형식의 저장 배치는 새 기본 배치로 갱신한다. 이후 사용자 배치는 다시 저장한다.

## 스크립트 편집

Content Browser의 `.cs` 더블 클릭, 파일 드롭, Inspector의 **소스 편집**으로 연다. Inspector는 클래스와 같은 이름의 파일을 `Scripts/`에서 찾으며, 후보가 여러 개면 직접 선택한다. C# 의미 분석으로 타입 정의를 찾는 기능은 아직 개발 중이다.

새 C#은 `Scripts/`에 `EntityScript` 템플릿을 만든다. 기존 파일은 덮어쓰지 않는다. 열린 탭을 다시 열면 기존 탭을 선택하고, 수정한 탭에는 `*`를 표시한다. 개별 저장·모두 저장, 닫기/종료 시 저장·버리기·취소, 외부 편집기 열기와 수동 다시 읽기를 제공한다.

코드 영역은 행 번호, 현재 행, C# 구문 강조, 네 칸 들여쓰기, 중괄호 다음 줄 자동 들여쓰기, 클래스·함수 목록, 검색·전체 치환을 제공한다. 치환은 한 번의 Undo로 되돌린다. `Ctrl+S`/`Ctrl+F`와 텍스트 Undo·복사·붙여넣기는 코드가 처리하며, W/E/R/Delete로 씬을 변경하지 않는다. 문서 편집 이력과 씬 이력을 분리한다.

UTF-8 파일을 지원하고 BOM과 LF/CRLF를 보존한다. 저장 시 외부 변경을 발견하면 덮어쓰지 않고 다시 읽기를 안내한다. 저장은 임시 파일 교체 방식이다. 파일 크기 상한은 4 MiB다.

## C# 빌드와 진단

**C# 빌드**는 열린 소스를 저장하고 `Scripts/GameScripts.csproj`를 비동기로 빌드한다. 에디터 옆 `managed/LuxEngine.ScriptCore.dll`을 참조하고 결과를 `.lux/managed/`에 둔다. `Scripts/NuGet.Config`가 있으면 해당 설정을 사용한다. 빌드 프로세스의 인수는 셸 문자열로 조합하지 않는다.

컴파일러 오류·경고는 문제 목록에 표시하며 활성화하면 해당 파일의 행·열로 이동한다. 게임 전체 CMake 빌드의 C# 진단도 이 목록에 연결한다. 전체 빌드의 출력은 실제 콘솔에도 표시한다. 플레이 중에는 어셈블리 빌드를 막고, 스크립트 빌드 중에는 플레이와 게임 전체 빌드를 막는다.

자동 컴파일·실행 중 어셈블리 핫 리로드·C# 언어 서버 기반 완성/정의/리팩터링·브레이크포인트 디버깅은 아직 개발 중이다. 빌드한 어셈블리는 다음 플레이 세션에서 사용한다. 외부 편집기는 OS의 `.cs` 연결 프로그램을 사용하며 IDE별 위치 이동 프로토콜은 구현하지 않았다.

## 참고한 작업 방식

- [Unity의 주요 창](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference): Scene/Game과 선택 대상의 Inspector 흐름.
- [Unreal Editor 인터페이스](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-editor-interface): 중앙 뷰포트, 도킹, 공통 재생 도구와 콘텐츠 서랍.
- [Godot 스크립트 에디터](https://docs.godotengine.org/en/stable/tutorials/editor/script_editor.html): 독립 스크립트 작업 공간, 파일·함수 목록, 문제 위치 이동.

창 이름을 섞기보다 문서·선택·콘솔의 역할을 일관되게 두는 데 적용했다. UI 구현은 `Editor/LuxUI`, 스크립트 작업 공간은 `Editor/Scripting`, 앱 연결은 `Editor/App`으로 분리했다.
