# 애니메이션 제작과 실행

애니메이션 작업 공간의 기본 화면을 독립 에셋 편집기로 연결했다. 왼쪽은 트랙·레이어와 FBX 본 계층, 가운데는 격리된 2D/3D 프리뷰와 Animator 그래프, 아래는 곡선·도프 시트, 오른쪽은 클립·키·이벤트·컨트롤러 설정이다. 기존 씬 변환 클립은 호환 탭에서 계속 편집한다.

## 에셋과 트랙

- `.luxanim`은 버전이 있는 JSON 클립 에셋이다. 씬에는 에셋 참조를 저장한다. 기존 씬에 포함된 변환 키도 읽는다.
- 위치·회전·크기·색상·투명도·스프라이트 프레임·실수 속성에 독립 트랙과 키를 둔다. 빈 대상은 소유자이며 `Rig/Arm`처럼 자식 경로를 바인딩한다.
- 키는 고정·선형·Cubic Hermite 보간을 지원한다. 회전의 선형 보간은 Quaternion의 최단 경로 Slerp를 사용한다. 곡선의 들어오는·나가는 접선을 편집한다.
- 시트의 행·열·FPS로 프레임 클립을 만들고 프레임 번호와 키 시간을 바꿔 순서·지속시간을 편집한다.
- 실수 속성은 스크립트 float 필드와 `camera.fov`, `camera.orthoSize`, `camera.nearClip`, `camera.farClip`, `material.metallic`, `material.roughness`를 바인딩한다.
- FBX 에셋을 선택해 클립을 재생하고 본 계층을 확인한다. 대상 본 경로에 변환 트랙을 추가하면 원본 FBX를 수정하지 않고 포즈를 덮어쓴다.

새 클립/Animator 생성, 열기, 저장, 씬에 연결을 제공한다. 에셋 브라우저의 더블 클릭과 파일 드롭으로도 연다. 저장은 임시 파일을 작성한 뒤 교체하며, 파일 참조는 에셋을 기준으로 해석한다. 변경 내용을 버리기 전에는 저장 여부를 확인한다.

## 키 편집과 미리보기

타임라인의 키를 다중 선택해 드래그·복사·잘라내기·붙여넣기·삭제한다. 키 이동은 FPS 간격으로 맞추며 다른 키를 넘어가 덮어쓰지 않는다. `Ctrl+휠`은 확대, 휠은 시간 범위 이동이다. Cubic 키의 접선 핸들이나 숫자 입력으로 곡선을 조절한다. 에셋의 Undo/Redo는 씬 편집 이력과 분리한다.

재생·일시정지·정지·이전/다음 프레임·스크러빙·속도·한 번/반복/왕복을 제공한다. 음수 속도는 역재생이다. 자동 키는 프리뷰의 기즈모 변경을 클립에 기록한다.

프리뷰는 선택 대상의 복제 씬을 사용한다. 선택 대상이 없어도 기본 도형 또는 FBX를 미리 볼 수 있다. 원본 씬의 Transform, 물리, 스크립트, Undo는 재생하거나 스크러빙해서 바꾸지 않는다. 씬에 연결은 별도 기록 편집이다. 스크러빙에서는 게임 이벤트를 호출하지 않는다.

## Animator

`.luxanimator`는 상태, 시작 상태, 전환 시간, Exit Time, 조건을 가진다. 파라미터는 Float·Integer·Boolean·Trigger다. 여러 조건은 AND이며 선택된 전환의 Trigger만 소비한다. 상태 전환은 크로스페이드한다.

그래프에서 상태를 선택·이동하고 Shift 드래그로 전환을 연결한다. 설정 패널에서 클립·속도·조건을 편집하고 시작 상태를 지정한다. 레이어의 가중치·가산 여부·본/대상 마스크와 파라미터 기반 1D Blend Tree를 제공한다.

FBX 블렌딩은 본의 로컬 Transform을 섞고 계층을 다시 계산한 뒤 스키닝한다. 모프는 스키닝 전 좌표에서 섞는다. 회전하는 팔다리의 최종 정점을 단순히 교차 보간하는 방식은 사용하지 않는다. 가산 본 포즈는 바인드 포즈를 기준으로 적용한다. 일반 가산 트랙의 위치·회전은 오프셋이며 크기는 배율이다.

## 실행·루트 모션·C#

`AnimationComponent.assetPath` 또는 `AnimatorComponent.controllerPath`를 연결한다. 게임 실행/PIE에서는 실행 씬의 플레이어가 평가하며, 서로 다른 엔티티와 씬의 가변 재생 상태를 공유하지 않는다.

이벤트는 순방향·역방향·반복·왕복 구간을 순회해 전달한다. 한 번 재생은 끝에서 멈춘다. 루트 모션은 루프 경계에서도 누적 이동을 보존한다. FBX는 지정한 루트 본(생략 시 루트 본/메시 노드)의 이동을 추출하고 스켈레톤에서는 제거한다. 동적 Rigidbody는 추출한 이동을 속도로 전달해 Jolt가 위치를 결정한다. 다른 대상은 Transform에 적용한다.

```csharp
Entity.Animator.SetFloat("speed", movementSpeed);
Entity.Animator.SetTrigger("jump");
Entity.Animator.Play("Run", 0.2);
Entity.Animator.Speed = 1.0;
```

`EntityScript.OnAnimationEvent(string name, string payload)`로 이벤트를 받는다. `Pause`/`Resume`, Integer·Boolean 설정도 제공한다.

## 범위와 검증

현재 제작 범위는 클립·트랙·곡선·스프라이트·FBX·Animator·게임 실행까지다. IK, 리타게팅, 리깅 제작, 가중 Bezier 시간 핸들, 2D 스킨 메시 제작, GPU 스키닝 최적화는 별도 확장 범위다. 기존 씬 변환 클립 탭은 이전 형식 편집용이며 새 기능은 에셋 편집기에서 사용한다.

검증은 이번 애니메이션과 64비트 좌표·렌더링 경로에 한정한다. 기존 전체 GPU 스트레스와 원격 CI는 실행하지 않는다.

## 별도 FBX 모션 파일의 런타임 재생

C++ 런타임에서 메시가 포함된 FBX는 ModelAsset::LoadFbx로, 별도로 배포된 모션 FBX는 ModelAsset::LoadFbxAnimation으로 읽는다. 모델에서 EvaluateAnimation(source, seconds, clip, pose, error)를 호출하면 원본 리그에서 클립 상대 시간을 평가해 스킨 메시를 포함한 ModelPose를 얻는다. 클립 번호와 길이는 모션 파일의 animations 목록에서 얻을 수 있다.

두 FBX는 동일한 리그에서 내보내야 한다. 스킨 본을 이름과 부모 경로로 연결하며 본이 빠지거나 같은 경로가 중복되면 오류를 반환한다. 서로 다른 리그의 리타게팅과 외부 모프 트랙은 지원 범위에 포함되지 않는다. Frontier County의 Characters.cpp에서 별도 Idle·Walk 모션을 리깅된 메시와 조합하는 예를 볼 수 있다.
