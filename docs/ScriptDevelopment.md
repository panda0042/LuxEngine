# C# 자동 완성과 디버깅

스크립트 편집기에서 LSP 기반 의미 분석과 DAP 기반 디버깅을 연결했다. 문자열 목록을 자동 완성처럼 표시하거나, 에디터의 C++ 실행을 중단점 디버깅으로 대신하지 않는다.

## 개발 도구 준비

- [csharp-ls](https://github.com/razzmatazz/csharp-language-server): Roslyn 기반 C# 언어 서버다. 이번 검증에는 0.28.0을 사용했다.
- [netcoredbg](https://github.com/Samsung/netcoredbg): CoreCLR DAP 디버그 어댑터다. 이번 검증에는 공식 3.2.0-1092 배포본을 사용했다.
- .NET 10 SDK, 에디터 옆 `managed/LuxEngine.ScriptCore.dll`이 필요하다.

언어 서버를 별도로 설치하는 예:

```sh
dotnet tool install csharp-ls --version 0.28.0 --tool-path .deps/script-tools
```

netcoredbg는 공식 릴리스의 해당 OS·CPU 배포본을 압축 해제한다. 공식 배포본에 없는 조합은 upstream 빌드 안내를 따른다. CMake 구성·빌드에서 이 도구들을 다운로드하지 않는다. 에디터는 도구가 없어도 열리며 해당 기능을 요청할 때 경로를 안내한다.

스크립트 툴바의 **C# 도구 설정**에서 두 실행 파일을 지정한다. `LUX_CSHARP_LS`, `LUX_NETCOREDBG` 환경 변수도 사용할 수 있다. 탐색 순서는 환경 변수 → 에디터 설정 → 실행 파일 옆 `tools/` 및 개발 저장소의 `.deps/script-tools` → PATH다. Windows는 `.exe`를 사용한다.

## 자동 완성과 정의 이동

- `Ctrl+Space`는 의미 분석 자동 완성이다. `.` 또는 식별자를 입력하면 잠시 뒤 자동으로 요청한다.
- 항목을 선택하면 서버의 편집 범위를 적용한다. `using` 추가 등 부가 편집도 한 번의 Undo로 되돌리며 커서는 완성한 코드 위치에 남는다.
- `F12`로 소스 정의에 이동한다. 다른 C# 파일이면 해당 탭을 연다.
- 열린 문서의 저장 전 내용을 버전과 함께 서버로 전달한다. 요청 이후 문서나 커서가 바뀐 자동 완성 응답은 적용하지 않는다.
- 서버의 컴파일 진단도 문제 목록에 표시한다.

프로젝트의 `Scripts/GameScripts.csproj`를 기준으로 분석하며 `LuxEngineScriptCore` MSBuild 환경 속성에 코어 DLL 경로를 전달한다. 처음에는 서버의 프로젝트 로딩 시간이 필요하다. 로컬 소스가 없는 외부 어셈블리의 역컴파일 뷰, 의미 기반 이름 변경·참조 찾기, 스니펫 확장은 아직 개발 중이다.

## 중단점 디버깅

1. 씬에 C# 컴포넌트를 붙이고 클래스 이름을 지정한다.
2. 코드 여백 클릭 또는 `F9`로 중단점을 설정한다. 여백 오른쪽 클릭은 C# 조건식을 설정한다. 중단점은 파일별로 저장하고 줄을 추가하면 함께 이동한다.
3. 아래 **스크립트 디버거** 탭에서 **디버그 실행**을 누른다. 소스를 저장하고 Debug DLL·PDB를 빌드한 뒤 현재 씬을 별도 LuxPlayer에서 실행한다.
4. 게임 호스트가 C# 어셈블리를 로드하면 디버거를 연결하고 중단점을 설정한 후 실행한다. 최초 생성 콜백 전부터 연결을 기다린다.
5. 중단 시 호출 스택, 현재 실행 줄, 스코프·변수를 표시한다. 변수 트리를 펼쳐 멤버를 확인하고 입력란에서 C# 식을 평가한다.
6. 계속·일시정지·프로시저 단위·한 단계씩·단계 나가기·중지 버튼으로 제어한다.

빈 중단점 표시는 아직 어댑터가 검증하지 않은 위치이고, 채워진 표시는 검증된 위치다. DLL이 로드된 뒤 도착하는 검증 이벤트도 반영한다. 실행 중 소스를 바꿔 PDB와 어긋나지 않도록 디버깅 세션 동안 소스 편집을 잠근다.

에디터 내부 PIE 프로세스에는 붙지 않는다. 게임을 중단해도 에디터의 UI 이벤트 루프가 멈추지 않도록 프로세스를 분리했다. 일반 별도 창 실행도 프로젝트의 `.lux/managed/GameScripts.dll`을 명시한다. 게임 창 종료·디버그 중지·프로젝트 전환 시 세션을 정리한다.

`LUX_SCRIPT_DEBUG_WAIT=1`은 별도 디버그 게임에만 전달한다. 연결 대기는 30초로 제한한다. Linux에서는 해당 프로세스의 부모 에디터와 그 디버거 자식에만 ptrace 권한을 허용한다. 시스템의 ptrace 설정은 바꾸지 않는다. 이는 [Yama의 프로세스별 허용 방식](https://docs.kernel.org/admin-guide/LSM/Yama.html)을 사용한다.

## UI 수정과 검증

씬 선택에 따라 기존 씬 클립 패널만 비활성화한다. 독립 애니메이션 에셋 편집기는 선택이 없어도 새 클립·재생·편집을 사용할 수 있다. 애니메이션 작업 공간을 숨기면 프리뷰 재생을 중지한다.

전체 앱의 공통 스타일을 자식 컨트롤 생성 전에 적용하고, 애니메이션 상단 도구를 넘침 메뉴에서도 실행 가능한 액션으로 바꿨다. 코드 편집기의 글꼴·스타일 변경 때 행 번호 여백과 탭 폭을 다시 계산한다. Windows 고배율·좁은 창에서의 공통 문제를 줄이는 변경이며, Windows 네이티브 실행 검증은 별도로 필요하다.

관련 검증은 실제 언어 서버의 다른 파일 멤버 자동 완성·정의 이동, 실제 CoreCLR 네이티브 호스트에 대한 조건부 중단점·호출 스택·변수 평가·단계 실행, 선택 없는 애니메이션 버튼의 마우스 입력이다. 외부 도구가 설치된 경우 `Editor_script_tools` 통합 테스트를 등록한다.
